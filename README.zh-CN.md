# 两人日历

公开访问的双人日历 Web App。游客可浏览空白日历；保存记录前，以邮箱或带国家区号的手机号加密码注册本站账号。两人通过邀请码配对，各自在不同设备登录。标记和备注默认私人，可逐条共享；经期预测默认私人，可在资料中选择共享。新访客默认英文，中、英、法语可在设置中切换，已有账号的语言选择在不同设备同步。D1 持久化数据。

## 本地验证

```sh
bash scripts/build.sh
node scripts/validate-artifact.mjs
node tests/integration.mjs
```

`tests/preview.mjs` 可在允许监听本机端口的环境中提供本地预览。它使用临时 SQLite 数据库，不连接生产数据。

## 账号和数据

- 未配置发信服务时，邮箱或手机号账号注册后立即可用；联系方式尚未验证。注册时展示一次性恢复码，用户必须保存它才能在忘记密码后重设。此模式没有邮件或短信找回，亦不适合需要验证真实联系方式的场景。
- 配置发信服务后，新邮箱账号使用 24 小时内有效的验证链接，验证后方可登录；验证过邮箱的账号可通过 30 分钟内有效的邮件链接重设密码。未验证邮箱的账号仍只能用恢复码找回。手机号注册届时暂停，直到接入短信验证。
- 密码和恢复码分别以随机盐加六段各 100,000 次 PBKDF2-SHA256 哈希保存，以符合当前 Worker 单次调用上限；会话使用随机令牌，数据库只存其 SHA-256 哈希。会话 Cookie 设为 `Secure`、`HttpOnly`、`SameSite=Lax`，30 天到期。
- 登录和恢复请求按 IP 及账号限速。写入请求检查同源 `Origin`。账号删除会删除其会话、凭据、标记和备注；解绑将双方已共享备注改为私人。
- 新标记和历史标记默认私人；共享需由创建者逐条开启。经期预测与标记的共享设置相互独立，预测共享需用户主动开启，解绑时自动关闭。
- 现有 ChatGPT 身份创建的历史记录保持在旧用户行内，公开版不会自动把它们关联到新的本站账号。迁移需要另行设计并验证身份。

## 发布

保留 `.openai/hosting.json` 中的 Sites 项目 ID 和 D1 绑定。通过 Sites 源码工作流构建、保存、部署；保留站点的 `public` 访问模式。`drizzle/0002_privacy_email.sql` 和 `drizzle/0003_language.sql` 在部署时追加到现有数据库。

生产发信需要在 Sites 运行环境中配置 `RESEND_API_KEY`（secret）、`MAIL_FROM`（已验证域名下的发件地址）和 `PUBLIC_SITE_ORIGIN`（本站 HTTPS 网址）。不要把密钥写入源码。未配置发信服务时，注册和恢复码可用；配置完成后须实际测试收信和重设流程。`drizzle/0004_contact_verification.sql` 将联系方式验证状态与账号可用状态分开，防止未验证邮箱获得邮件找回资格。
